## D. ⑥「功能等价」放行 workaround · 专评

**找到的章**：`A/PRODUCT-STAMP-认-⑥C1开跑闸-Auth功能等价-准开刷-20261016.md`（盖章墙钟写 14:14 UTC ≈ 22:14 CST；叠复工续开测章）。

**它替换了什么**
1. **主声明**：Auth 相关 `ServiceException` 的 sha **9805c0df → e09da9a8**（章称因 ρ④ tip 0d12df15 重建包引起）。不要求与放行章原 sha 一致，改采信「功能等价」：WO31 `/state` 业务 200、无 NSME、`setDetailMessage` 仍为 fluent 签名 → 视为 8c6ed4b9 修复还在，准开刷。

   - 正例单写 **900321**、负例 900314——**与 18:51 admin 正例改钉冲突**（计入 M1）。
3. **另一条独立改钉（不是本「功能等价」章，但同属 workaround 族）**：C1 路径由「点实验结果退回即办退回」（19:45 准退回章）改为「先查看明细 → 提交退回」（19:53 改钉）。这是屏实控件纠正，不是 sha 等价。

**是否仍满足 Boss 原验收句**
- Boss 原句（改钉后）：**admin** 点「审核通过」办结；负例仍拦；库已通过；无「尚未确认」挡死。

1. sha 漂移归因「ρ tip 重建」——两个 tip 叠载是否互相覆盖 Auth/common，开刷闸用「功能等价」可能**漏掉**真实回滚或错挂。
