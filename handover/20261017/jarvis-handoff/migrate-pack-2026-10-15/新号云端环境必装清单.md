# 新号云端环境必装清单 · 大白话 · 2026-10-15

给 Jarvis / 新号装机用。密钥不写。案1不动。禁 tip/sha 堆砌。

依据：云端出包 PLAN / GATE / CHECKLIST（产品已准基线）；安卓另线须单独产品章。

---

## 一句话

新号云端 **先装 Web/Core 出包线**（JDK8 + Maven + 本地依赖仓预热）。Node 是打前端才要、不挡主线。安卓云端 **没产品单独盖章就别装第二套**，别蹭 Web 的 JDK8。

---

## 1. 必须装（Web / Core 出包线）

| 装什么 | 版本口径 | 怎么算装好 |
|---|---|---|
| JDK | Temurin **JDK 8**（必须是 1.8，不是 11/17） | `java -version` 能看到 1.8；失败就停，禁止边跑边装 |
| Maven | **3.9.x**，且跑在 Java 1.8 上 | `mvn -version` 见到 Maven 3.9 + Java 1.8 |
| 内存参数 | 默认 `MAVEN_OPTS=-Xmx2g`（机器紧可再调） | 出包时不再临时瞎改 |
| Maven 本地仓 | 持久化 `~/.m2/repository`（进 Environment Build 快照） | 目录在；后续任务冷下载接近 0 |
| 环境入口 | 仓库默认分支的 Environment（install 脚本幂等装工具 + 预热依赖） | Builds 绿；每个出包任务开局烟测过 |

**开局烟测（每个出包任务先跑，不过就停）：**

```bash
java -version 2>&1 | head -3    # 必须见 1.8
mvn -version | head -5          # 必须见 Maven 3.9 + Java 1.8
test -d "$HOME/.m2/repository" && echo "m2_ok"
```

**标准出包命令（装好后）：** 对主模块做一次 `package`（可跳过测试编译）；禁止「先全量测再打包」双跑。跳过测试 **不能代替** 交运维前的三线自测。

---

## 2. 按需装（不挡主线）

| 装什么 | 何时要 | 口径 |
|---|---|---|
| Node + `node_modules` 持久化 | 只有打前端 dist 时 | 和 Maven 仓同理预热；**首期不阻塞** Environment 主线 |
| 构建产物目录复用（`target`） | 同分支连续小改时可保留 | 换分支 / 大合入 / 依赖大变 / 怀疑脏构建 → **必须 clean** |

---

## 3. 安卓线（须产品单独盖章才开）

| 项 | 口径 |
|---|---|
| 现网习惯 | 仍是本机出包 + 真机调试这条；**不等于**已准云端安卓 |
| 若产品单独盖章开云端安卓第二线 | Temurin **JDK 17** + Android SDK（约 36）+ Gradle 持久缓存 |
| 硬规矩 | **不蹭** Web/Core 的 JDK8 环境；没章就别在新号云端装安卓工具链当默认 |

---

## 4. 预热逻辑（install 里做什么）

说人话：**有代码就对着工程预热依赖；默认分支经常没业务代码时，就从「包装基线分支」稀疏拉一份来预热，别空转。**

按序（脚本须可重复跑、缺啥补啥）：

1. 确认 JDK8 / Maven 3.9 已在 PATH（没有就幂等装好，装不好 **退出失败**）。
2. 固化 `JAVA_HOME`、`MAVEN_OPTS`。
3. **预热依赖：** 对父工程 + 主模块做「离线依赖」或一次跳过测试的 package，把常用包灌进 `~/.m2`。
4. （可选）默认分支再暖一次常见编译产物，只为冷启动快；业务分支仍按门禁决定要不要 clean。
5. **不要**把整仓 COPY 进镜像；工具在环境层，代码仍由每次检出。
6. `start` 一般留空：依赖下载只放 `install`，别每次开机重下。

**预热分支规则（Boss/门禁已钉）：**

- 检出里 **已有** 主工程 → 直接对该工程预热本地仓。
- 检出里 **没有** 业务代码（空默认分支常见）→ 从约定的包装基线分支拉依赖做预热，再快照进 Build。

## 5. 缓存验收口径（过线才算装对）

| 查什么 | 过线标准 |
|---|---|
| 环境烟测 | JDK 1.8 + Maven 3.9 过；本地仓目录在 |
| 开工到能开打 | 从任务开工到能启动 `mvn package` **≤ 5 分钟**（含烟测和依赖就绪；**不含**写代码思考时间） |
| 热仓重编 | 只改 1 个已有类再 package，**命令段墙钟 ≤ 2 分钟**（目标体感常在 30–90 秒） |
| 冷仓 vs 热仓 | 交接单分两栏报：**冷仓首包** 与 **热仓重包**；别把写码时间算进出包 |
| 大 jar 交件 | 单文件大约超过 100MB → 必须压缩；还大就分片；交出去的文件 **不能是 0 字节** |
| 诚实口径 | 缓存主要压「改完就打」；**解决不了**「从零写新接口要想很久」 |

---

## 6. 新号落地顺序（建议）

1. 把旧号已准的 Environment / 安装脚本迁到新号仓库默认分支（或按 CHECKLIST 重建同一套）。
2. 触发一次 Environment Build，烟测绿。
3. 做一次「只改一个类」的热仓实测，把冷/热墙钟写进交接。
4. Node、安卓按上面「按需 / 须盖章」再开，不抢主线。
5. 密钥、云厂商可扮演凭证：**新号用安全方式重注，旧号秘密不迁、不写进本清单。**
