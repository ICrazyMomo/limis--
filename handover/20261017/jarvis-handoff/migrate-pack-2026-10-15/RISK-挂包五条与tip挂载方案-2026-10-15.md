## 结论（大白话）

两套方案整体风险 **可控偏中**：真正吓人的不是 gzip 本身（压缩只用于交件/传包，挂前会解压还原，**不会**让 Java 去加载 `.jar.gz`），而是 **一键脚本误换错包/冲掉叠层**，以及 **预检误判把该挂的拦住或该拦的放行**。  
五条里「少整换、先合包、写时刻」对稳定性偏保护；「一键脚本」要有干跑/确认闸才安全。实施必须 **先模板与预检，后总控替换**，禁止一上来全自动挂公网。

严重度口径：高=可能造成公网不可用或错挂冲层；中=延误/误拦/返工；低=书证/体验问题。

## A. 方案① 挂包优化五条

| 风险 | 严重度 | 说明 | 缓解 |
|---|---|---|---|
| 交件 gzip 失败/解压错仍当成功 | **中** | 解压后未对 sha 就挂，等于挂坏包 | **解压/合并后必须一次 sha=HANDOFF**；0 字节/解压失败=FAIL 停挂 |
| gzip 被误以为「Java 直接跑 gz」 | **低**（认知） | 若有人把 `.jar.gz` 当 `-jar` 参数会起不来 | 手册写死：节点上只跑还原后的 `.jar`；脚本禁止对 gz 执行 java -jar |
| 少整换 → 漏换该换的依赖 class | **中** | overlay 漏文件导致「挂了但行为旧」 | MANIFEST 清单 + 挂后抽核；产品/研 HANDOFF 列齐 class |
| 一键脚本误操作（错路径/错 tip/未备份） | **高** | 直接威胁现网稳定性 | 默认 **dry-run**；备份校验存在才替换；关键步需 `--i-know` 或双人；先影子目录试跑 |
| 先合包拖延紧急热修 | **中** | 冲突停挂导致该上的修上不去 | 挂序单支持「紧急插队」书面例外；预检输出阻塞原因给人看 |
| LIVE 缺时刻被卡死 | **中** | 过严退回导致协调以为没挂 | 区分「探活已过但书证缺字段」=补写，不自动回滚；缺字段禁宣称闭环，不禁已成功的进程 |
| 五条与手册 §4–§5 口径打架 | **低** | 执行人不知听谁的 | 五条管纪律，热换细节仍以手册为准（运维确认备注已写） |

## B. 方案② tip 挂载一键化（总控+三模式等）

| 风险 | 严重度 | 说明 | 缓解 |
|---|---|---|---|
| **现网稳定性：总控误挂错模式** | **高** | web 当成 core-full 或 overlay 当成裸换 → 服务中断/冲层 | HANDOFF 强制声明 mode；总控校验 mode∈{web,core-full,core-overlay}；与禁冲列表交叉；默认 dry-run |
| **业务代码误伤** | **低～中** | 方案约定不自动合码；误伤来自「错把整包裸换冲掉 A′/NUMERIC/交接」 | 预检 BLOCK；禁自动合业务码（方案已写）；整包须「可裸换底」旗标 |
| **脚本自动化误操作** | **高** | 一键跳过确认、并行 scp 弄死 Mac、杀错 PID | 分步可断点；杀进程前核对端口 20160 cmdline；传包默认单文件/≤2 片；并行传包默认关 |
| **gzip 对 Java 启动/类加载** | **低**（在正确流程下） | gzip **只用于交件与传输**；还原成标准 zip/jar 后再挂。Java/Spring 不加载 gz。本箱测压缩比约 90%，不改字节码 | 挂前强制解压+testzip/sha；禁止 `-jar *.gz`；回归：还原 sha=交件声明 |
| **预检误判：该挂不挂** | **中** | 台账陈旧 → 假冲突 → 干等（类 NUMERIC 半小时） | 台账以最近 OPS-LIVE+现网 jar 抽核为准；误拦可「产品/协调书面 override」并记审计 |
| **预检误判：该拦没拦** | **高** | 漏读禁冲 → 冲掉旁路/交接 | 禁冲列表双源：HANDOFF + 现网叠层台账；overlay 挂后必抽 MANIFEST；失败自动提示回滚备份 |
| **LIVE 两字段缺失卡死流程** | **中** | 测试/协调卡在「没 LIVE 件」 | 脚本自动写时刻；人工补写通道；**已探活成功不因缺字段回滚**；只退回书证 |
| **实施顺序依赖** | **中～高** | 先上全自动替换、后做预检 = 高危；产品未盖章先改现网 = 违规 | 顺序钉死：①产品盖章 → ②LIVE 模板+预检 → ③dry-run 总控 → ④单枪试跑 → ⑤默认启用；确认前不改现网 |

## C. 按你点名的维度对照

| 维度 | 总判 | 要点 |
|---|---|---|
| 现网稳定性 | 中高风险点在「替换/重启」自动化 | 备份+dry-run+模式校验；探活失败走回滚 |
| 业务代码误伤 | 低（方案禁自动合码） | 真风险是错挂冲层，不是改源码 |
| 脚本误操作 | 高（若无闸） | 确认闸、端口核对、禁默认并行碎传 |
| gzip→Java/类加载 | **低** | 不解压就挂才危险；规范流程无影响 |
| 预检误判 | 误拦中 / 误放高 | override 审计 + 挂后抽核 |
| LIVE 缺字段卡死 | 中 | 补写≠回滚 |
| 实施顺序 | 中高若颠倒 | 先预检与模板，后自动替换 |
